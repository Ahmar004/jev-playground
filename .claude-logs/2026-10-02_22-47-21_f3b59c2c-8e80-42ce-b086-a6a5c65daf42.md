The rules are in `scripts/check-commit-message.mjs` (the `commit-msg` hook), with the explanation in `docs/rules/commits.md`.

## Format

```
type(scope)!: subject
```

## Types (fixed list)

| Type       | Use for                                       |
| ---------- | --------------------------------------------- |
| `feat`     | A new feature                                 |
| `fix`      | A bug fix                                     |
| `perf`     | A performance improvement                     |
| `refactor` | A code change that doesn't change behavior    |
| `style`    | Formatting, or visual/CSS-only changes        |
| `docs`     | Documentation only                            |
| `test`     | Adding or fixing tests                        |
| `build`    | Build system, dependencies                    |
| `ci`       | CI config                                     |
| `chore`    | Maintenance, logs, releases                   |
| `revert`   | Reverting an earlier commit                   |

## Scopes

- **Optional.** `docs: update readme` is valid.
- **Any lowercase kebab-case word is allowed** (`[a-z0-9-]`), plus an optional sub-scope like `levels/quiz`. The `SCOPES` allowlist at `scripts/check-commit-message.mjs:26` is empty, so the hook doesn't restrict scope names.
- These are the scopes this repo has used so far, so new commits stay consistent and searchable:
  `logs`, `runner`, `levels`, `race`, `ui`, `e2e`, `progress`, `shell`, `record`, `games`, `content`, `auth`, `arena`, `sandbox`, `quizzes`, `methodology`, `developer-mode`, `db`, `design`, `release`

## Other rules the hook checks

- The whole header must be 72 characters or fewer.
- The subject must start with a lowercase letter, be in the imperative ("add x", not "Added X") and have no trailing period.
- Add `!` before the colon for a breaking change, e.g. `feat(api)!: ...`.
- If you add a body, put a blank line between the header and the body.
- Messages starting with `Merge `, `Revert `, `fixup!`, `squash!`, `amend!` or the exact text `Initial commit` skip the check. That's why "Initial version" was rejected but "Initial commit" would have passed.
